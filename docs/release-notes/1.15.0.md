# LogCollector 1.15.0

## Endpoint Data Sprawl user file drilldown

- Extends `EndpointDataSprawlRemediator_CL` and the durable SQL read model with file name,
  extension, source-created time, and source-modified time.
- Applies the SQL column additions idempotently to existing databases and persists the new values
  during replay-safe batch ingestion.
- Adds the dashboard contracts `GetEndpointDataSprawlUserSummary`,
  `GetEndpointDataSprawlUserDevices`, and `GetEndpointDataSprawlUserDeviceFiles`, including
  deterministic offset pagination and optional static filters.
- Adds an execute-only `endpoint_data_sprawl_reader` role without direct table access.
- Allows database initialization to optionally create a dashboard managed-identity contained user
  from its name and application/client ID while preserving Worker-only standalone deployments.
- Adds an mTLS and delegated-token user-session registration endpoint that binds the token
  `deviceid` claim to the trusted certificate device before applying the established tenant/user
  HMAC contract.
- Stores only a hash of the random opaque registration ID in server-side session state and carries
  the resolved correlation on the trusted queue pointer; administrative telemetry remains nullable
  and cannot enter user placements.
- Retains only the Frontend's `Device.Read.All`; the Worker no longer reads Intune primary-user
  assignments.
- Updates LogCollector Core / Client to 1.12.0 with
  `Register-LogCollectorUserSession`, `Revoke-LogCollectorUserSession`, and envelope-bound
  `-UserSessionRegistrationId` spool replay without persisting delegated access tokens.
- Aligns dashboard summary procedure columns and KPI semantics around the durable latest-placement
  snapshot, uses exclusive upper date bounds, preserves metadata from older clients, and retains
  file placements independently of event retention with a separate longer bounded retention.
- Keeps invalid, expired, revoked, or device-mismatched registrations fail-closed for user
  correlation while accepting the telemetry as uncorrelated administrative data.
- Stores the user-correlation HMAC in a deterministic EDSR Key Vault secret, grants the Frontend
  only Key Vault Secrets User, and configures the Function App through a Key Vault reference.
- Adds a dedicated deterministic EDSR Azure App Configuration store with a unified
  `appcs-mslabs-edsr-prod` override, labeled non-secret user-session and SQL-retention keys,
  managed-identity Data Reader access, restart-based native Function App references, and shared
  store outputs. Secrets, SQL connection state, enablement, and table invariants remain outside
  App Configuration.
