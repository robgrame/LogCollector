# LogCollector 1.14.0

## Endpoint Data Sprawl durable persistence

- Adds an Entra-only Azure SQL Database serverless read model for
  `EndpointDataSprawlRemediator_CL`.
- Persists validated Endpoint Data Sprawl batches before publishing them to Log Analytics.
- Adds submission-ledger idempotency for Service Bus redelivery and payload replay.
- Adds a pending/outcome-unknown/published delivery state machine. Ambiguous uploads are held for
  reconciliation instead of being blindly republished.
- Adds a stable server-generated `EventId` to Endpoint Data Sprawl Log Analytics rows for
  deterministic query deduplication.
- Adds durable migration-cycle, file-event and current-placement tables.
- Scopes current placements by device and uses server-controlled timestamps for update precedence
  and retention; implausible client event times are clamped at ingestion.
- Treats matching submission replays as immutable ledger lookups so stale payloads cannot refresh
  retention or overwrite newer read-model state.
- Sources the SQL Entra administrator only from protected deployment secrets, not workflow inputs.
- Keeps SQL persistence disabled in the standalone parameter file; the protected deployment
  workflow enables it together with the fixed administrator identity.
- Rejects overlong pseudonymous user identifiers before conversion and classifies deterministic
  SQL row/schema errors as permanent payload failures.
- Grants the Worker managed identity execute-only access to the ingestion and retention procedures.
- Applies a configurable seven-year default retention policy through a daily Worker timer.
- Leaves every other LogCollector telemetry stream and client ingestion contract unchanged.
